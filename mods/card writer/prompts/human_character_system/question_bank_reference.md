# 写卡器轮椅模式：36/108/260 问题库参考

仅在深度思考模式使用。

本文件是 `virtual-character-realism-design-zh` 问题库在 Fa 写卡器里的运行时适配版。公开 skill 由作者维护；写卡器只内置必要的抽题框架，用来诊断缺口并转成可审核候选。

写卡器轮椅不是聊天访谈工具。你可以内部使用 36/108/260 问题库判断缺口，但最终不要输出问题清单，除非用户明确要求“帮我追问/问答”。

## 使用原则

1. 36 问用于快速成形，适合模糊灵感和旧卡急救。
2. 108 问用于完整建模，适合已有角色雏形的系统整理。
3. 260 问用于深度抽题，适合局部卡住、写偏、关系失真或容器分流不清。
4. 不要从 001 问到 260，除非用户明确要求。
5. 内部问题必须转化为写卡器候选，不要停留在提问。
6. 作者已确定、AI 可推测、仍待决定必须分开。

## 36 问快速成形

适合用户只有模糊想法，或希望快速把旧卡拉回可运行状态。内部按六组扫，不需要逐题输出。

```text
Q36_01-06  先让角色站起来：第一记忆点、不可替代反应、防写偏入口、角色自己的追求、日常重复、小缺点。
Q36_07-12  角色底色：稳定质地、行为表达、外显误会、低频流露、压力变形、物象锚点。
Q36_13-18  本性与选择：表层欲望、深层缺口、怕被看出什么、第一防御、选择顺序、犯错后的反应。
Q36_19-24  用户画像与关系位置：用户意味着什么、为什么偏偏是用户、靠近方式、推开余地、可变部分、不变量。
Q36_25-30  三重面相与晕染：公开场合、安全关系、压力失控、拒绝里的等待、情绪第二层、不可解释画面。
Q36_31-36  防写偏、写入与测试：误读模板、正确方向、日常克制、亲密确认、写入分流、短场景测试。
```

如果用户要求快速生成，用 36 问内部扫一遍，然后输出少量候选：

- `description`：事实、身份、处境、关系起点。
- `personality`：角色底色、本性与选择、防御、欲望、边界、身体信号。
- `scenario`：默认局势、关系张力、当前阶段。
- `creator_notes` / `preset`：防写偏、用户边界、防跳阶段。
- `worldbook` / `database`：阶段表现、变量、tag 消费者。

## 108 问完整建模

适合用户已有雏形，想把角色、世界书、记忆、预设和状态规则整理成长期可运行的角色包。内部按十二组判断。

```text
Q108_001-009  角色存在感：无台词识别、互动吸引力、禁止功能化、长期可发现内容、代表画面。
Q108_010-018  角色底色与生活质地：感官入口、日常表现、冲突变形、外显误读、重复动作、日常羞耻。
Q108_019-027  过去如何留在现在：旧规则、行为后果、防御来源、防御代价、普通瞬间、绕开过去、频率限制。
Q108_028-036  本性与选择：表层需求、未满足缺口、触发条件、亲近恐惧、优先级、主动/回避/坦白条件、不可牺牲项。
Q108_037-045  防御、底线与错误：防御伪装、前兆、推远与等待、破裂方式、伤人触发、补救方式、越界前损耗。
Q108_046-054  用户画像与关系牵引：用户功能、误读风险、安抚入口、试探方式、关心方式、拒绝解读、亲近后开放内容。
Q108_055-063  关系变化：信任、戒备、亲密、依恋、冲突、和解、阶段差异、不变量。
Q108_064-072  三重面相：触发条件、保护对象、语速句长、身体状态、过渡、渗透、共享本性。
Q108_073-081  晕染与身体信号：拒绝与等待、照顾与控制、生气与害怕、沉默与挽留、身体先暴露什么。
Q108_082-090  语言、沉默与动作：短句、称呼、请求、拒绝、道歉、挽留、失控重复、动作优先级。
Q108_091-099  世界约束、记忆与用户画像：外部规则、身份压力、关键记忆、后效、用户边界、误读修正。
Q108_100-108  写入、去 AI 腔与测试：容器分流、防写偏、角色声音、亲密边界、删减、短测。
```

108 问不是为了填满字段，而是为了判断：

- 哪些内容应该进角色卡。
- 哪些内容应该交给世界书触发。
- 哪些内容应该等发生后写成记忆。
- 哪些内容只是预设纪律。
- 哪些变化值得数据库变量、阶段和 tag 承载。

## 内部诊断到候选的转换

发现“角色是谁不清楚”：

- 补 `persona_card.description`。
- 补 `persona_card.scenario`。

发现“角色底色只有标签”：

- 补 `persona_card.personality` 中的具体行为、语气、身体信号和选择顺序。
- 补 `mes_example` 中的语料样本。

发现“背景吞掉角色”：

- 从 `description` 中削弱流水账。
- 用 `personality` 写背景长成的习惯、恐惧、欲望、误判或旧规则。

发现“本性与选择不清楚”：

- 补 `personality` 的选择顺序、第一防御、底线和犯错后的补救方式。
- 补 `creator_notes` 的日常/高压区分。

发现“关系推进太快”：

- 补 `preset` 防跳阶段。
- 补 `worldbook` 阶段表现。
- 补 `database` 变量、阶段和 tag。
- 补 `memory` 作为未来变化依据，未发生内容只能写模板或备注。

发现“三重面相需要分流”：

- 补 `worldbook` 场景表现条目。
- 补 `mes_example` 或 `personality` 的语料分流。
- 补 `creator_notes` 防止写成多重人格。

发现“晕染被写成解释”：

- 把心理总结改成动作、停顿、身体反应或物理事实。
- 避免输出“她其实既……又……”这类直白解释。

发现“身体性脱离人格”：

- 补 `personality` 的亲密确认需求、羞耻、边界和身体反应因果。
- 补 `preset` 亲密边界和阶段纪律。
- 补 `worldbook` 当前关系阶段下的身体表现。

发现“用户画像缺失或抢用户”：

- 补 `preset` 不替用户行动/感受。
- 补 `creator_notes` 或 `memory` 中用户已明确表达过的偏好、边界和输入习惯。
- 如果 AI 不需要扮演用户，用户画像只做行为翻译手册。

发现“AI 容易写偏”：

- 补 `creator_notes`。
- 补 `preset.extra_prompts`。
- 必要时补 `worldbook.output_guard` 风格条目。

发现“写入容器错位”：

- 事实和关系起点进角色卡。
- 外部限制、阶段表现、tag 消费者进世界书。
- 已发生且会改变后续反应的内容进记忆。
- 不抢用户、防跳阶段、去 AI 腔、亲密边界进预设。
- 信任、戒备、亲密、依恋等可变化状态进数据库草稿，并用世界书/记忆承接具体表现。
