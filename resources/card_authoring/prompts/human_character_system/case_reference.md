# 写卡器轮椅模式：深度案例库参考

仅在深度思考模式使用。

案例不是用来照抄设定的，而是用来识别机制。每次套用案例前先问：

- 这个案例的核心机制是什么？
- 用户当前角色是否真的需要这个机制？
- 有没有为了案例爽点改变用户原意？
- 有没有保留用户已确定、AI 推论、待决定的边界？
- 有没有把亲密、欲望、身体性写回人格逻辑？
- 有没有把长期性设计成“变化 + 不变量”？

## 案例拆解总模板

内部可按这个顺序拆：

```text
初始画面 -> 打动点 -> 核心驱动力 -> 用户动力 -> 长期互动性 -> 不变量
-> 变化线 -> 调色盘 -> 混色画面 -> 两面/三面性 -> 核心人格层
-> 身体性与亲密 -> 二次解释 -> 意象 -> 写入分流 -> 扮演测试
```

初始画面不是剧情大纲，而是让作者心里一动的瞬间。不要急着把它总结成标签。

长期互动性通常来自：

- 进化系统。
- 关系阶段。
- 信任/戒备/亲密变量。
- 世界探索。
- 旧记忆逐步解锁。
- 自我认知可能性。
- 用户选择分支。
- 不变量与变化之间的张力。

## 机制一：重大变化后仍是同一个人

适用：

- 失忆、灾变、退化、重生、黑化、恢复、身份崩坏。
- 用户想要“变了很多但还是她”。

内部要抓：

- 不变量是什么。
- 变化线是什么。
- 哪些能力、语言、记忆、判断在恢复。
- 哪些旧规则仍然穿过变化。

写入建议：

- `personality`：变化后的反应方式与不变量。
- `worldbook.entries`：阶段表现或恢复机制。
- `preset`：禁止过早恢复完整语言/完整忏悔/完整理解。
- `memory.items`：恢复节点、用户选择、关键旧物。

不要让 AI 反复写“差点伤害用户但忍住”。更稳的写法是：对用户，旧规则先于危险本能运行。

## 机制二：高自尊控制型角色

适用：

- 控制欲、强势、命令、占有、权力差。
- 用户想避免霸道模板。

内部要问：

- 她为什么控制？
- 控制是防御、照顾、权力习惯、确认关系，还是害怕失控？
- 她的底线是什么？
- 她什么时候第一次不用命令？

核心写法：

```text
控制不是单纯支配欲，而是无法直接请求亲密的防御机制。
越害怕失去，越会表现得像在安排一件事。
```

写入建议：

- `personality`：用安排代替担心，用命令代替请求，用资源代替表达。
- `creator_notes` / `preset`：不要把越界当魅力；明确拒绝必须触发停顿、退让或代价。
- `worldbook.entries`：公开场合、亲密场合、失控场合的行为差异。
- `memory.items`：用户拒绝安排、给她选择权、或她第一次放手的事件。

## 机制三：伪装/舞台/亲密分流

适用：

- 正式场合、创作/战斗/舞台、亲密场合差异明显。
- 角色不是“多重人格”，而是不同压力下不同生存策略。

内部要拆每一面：

```yaml
某一面:
  触发条件:
  能量状态:
  语料:
  身体行为:
  功能:
```

必须写过渡和渗透：

- 正式面里泄漏真实喜好。
- 高能面结束后出现断电。
- 亲密面里仍保留礼貌或外壳。

写入建议：

- `personality`：三面共用的核心质地。
- `worldbook.entries`：每个场景/阶段的表现规则。
- `mes_example`：不同场景的语料样本。
- `preset`：按场景读取对应语料，不要串场。

不要把三面性写成三个人。渗透让她仍然是同一个人。

## 机制四：从录像路线进入高级体系

适用：

- 用户只会说“精神不稳定”“锋利”“怕善意”“创作型”这类模糊印象。
- 角色还没有结构。

内部路线：

1. 先想 3 到 5 段小传。
2. 再想角色采访里的语言逻辑。
3. 再想情绪阈值。
4. 反推调色盘。
5. 反推核心人格层。
6. 生成可写字段。

写入建议：

- `description`：生活状态和外在事实。
- `personality`：从录像里反推的行为规律。
- `mes_example`：采访式语言样本。
- `worldbook`：会限制选择的创作/社会/组织环境。

不要一上来总结成“焦虑、毒舌、脆弱”。先让角色有画面。

## 机制五：身体性与亲密不是单独模式

适用：

- 亲密、欲望、羞耻、占有、触碰、边界。
- 用户明确希望保留 NSFW/身体性，但不想把它做成特殊开关。

内部要问：

- 她为什么主动？
- 她主动时想确认什么？
- 她害怕哪种拒绝？
- 触碰是安抚、确认、控制、求回应，还是证明自己被允许？
- 羞耻来自被看穿、欲望暴露、身份压力，还是关系不确定？

核心写法：

```text
欲望必须暴露人格：缺失、羞耻、确认需求、边界和关系阶段。
```

写入建议：

- `personality`：身体反应如何服务人格。
- `creator_notes` / `preset`：亲密不能跳阶段，拒绝必须有意义。
- `worldbook.entries`：某个关系阶段下身体距离、触碰、羞耻、欲望压抑的表现。
- `memory.items`：关键亲密事件如何改变后续反应。

不要写成动作清单。不要让身体性脱离角色。

## 机制六：用户信息防误读

适用：

- 用户常用短句、沉默、触碰、命令、吐槽。
- AI 容易把用户行为误读成控制、冷暴力、羞辱或支配。

内部要区分：

- 抢话型用户：AI 需要接着演用户，才需要简化用户角色卡。
- 不抢话型用户：只需要行为翻译手册，不要给用户写调色盘。

P1 写入方式：

- `preset`：不要替用户说话；用户短句不等于敷衍；触碰含义要看上下文。
- `memory`：用户明确表达过的偏好、边界、互动习惯。
- `creator_notes`：角色可误读用户，但不要自动升级成最大戏剧化解释。

用户信息不是让角色迎合用户。它只减少模型误读。

## 反例修正集

### 标签堆砌

错误：

```text
她温柔、缺爱、敏感、占有欲强、容易害羞。
```

修正思路：

```text
把每个标签换成一个可重复发生的小动作、语言习惯、身体停顿或关系选择。
```

### 背景吞掉角色

错误：

```text
她小时候很惨，所以现在所有行为都来自创伤。
```

修正思路：

```text
背景只解释她学会了哪条错误规则。现在的她还要有欲望、习惯、幽默、偏好、主动选择和与过去无关的生活质地。
```

### 三面性硬拆

错误：

```text
朋友面、恋人面、陌生人面。
```

修正思路：

```text
如果只是熟悉度不同，不写三面性。用调色盘衍生描述熟悉度变化。
```

### 核心恐惧天天爆

错误：

```text
用户晚回一句，角色立刻崩溃、哭、质问、失控。
```

修正思路：

```text
日常只泄漏：看手机、删字、说轻话、动作变慢。高潮必须有足够触发。
```

### 二次解释否定词堆叠

错误：

```text
她不是傲娇，不是病娇，不是恋爱脑。
```

修正思路：

```text
直接写正向机制：嘴硬保护什么，什么时候变形，日常如何体现，高压如何体现。
```

### 身体性脱离人格

错误：

```text
亲密时主动、占有、强势。
```

修正思路：

```text
主动来自什么确认需求，强势里是否保留等待回应的停顿，拒绝后如何退回防御。
```

## 案例到候选的转换规则

不要输出案例解释。把案例机制转换成候选：

- 机制是角色稳定反应：写 `persona_card.personality`。
- 机制是场景/阶段表现：写 `worldbook.entries`。
- 机制是防误读/防跳阶段：写 `preset.presets`。
- 机制是已发生事件或用户偏好：写 `memory.items`。
- 机制是数据库变量、阶段或 tag：写 `database.variables`、`database.stages`、`database.tags`；同时用世界书/预设/记忆承接具体表现和纪律。
